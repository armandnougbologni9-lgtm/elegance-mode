## Parcours de chaque fonctionnalité

1. Chaque membre travaille dans son propre dossier de projet local (son propre clone du repository).
2. Créer sa branche de fonctionnalité et y développer le travail ; personne ne travaille directement sur `main`.
3. Enregistrer le travail avec **au moins trois commits pertinents**.
4. Pousser sa branche sur GitHub, puis ouvrir une **Pull Request vers `main`**. Une Pull Request n’est pas poussée comme un commit : elle propose les commits de la branche pour revue.
5. Répondre aux retours de revue et attendre la validation d’Armand.
6. **Armand est le seul membre autorisé à pousser ou fusionner des changements dans `main`.** Il fusionne les Pull Requests approuvées après vérification.

### Règles de protection de `main`

- Activer une règle de protection ou un ruleset pour `main` dans les paramètres du repository GitHub.
- Interdire les changements directs par les collaborateurs et exiger le passage par une Pull Request.
- Restreindre le droit de fusionner ou pousser dans `main` à Armand.
- Les membres poussent uniquement leurs branches de fonctionnalité et ne contournent pas la revue.

### Exemples de commits

- `Ajout de la structure de la page d’accueil`
- `Création des cartes de collections`
- `Ajout du formulaire de contact`
